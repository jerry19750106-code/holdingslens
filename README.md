把組合的「風險來源」拆開算給你看——**不預測漲跌，只回答你的風險押在哪裡。**

> 這是一個針對個人投資組合的風險結構診斷工具。市面上的投資工具都在比誰會「算漲跌」，沒有人在算「風險從哪來」——這個工具補上這一塊：輸入持倉金額（或直接填基金代碼），30 秒內拿到一張「風險帳單」：每檔資產出資多少 vs 承擔多少風險、危機情景下相關性飆升對組合的影響、名義檔數背後真正的獨立押注數，全部用可展開的公式算給你看。微信小程式、H5 網頁、本地腳本三端共用同一份 UMD 引擎（位元組級一致），全本地計算，持倉資料不上傳任何伺服器。

> ⚠️ **不是投資建議。** 本工具只做風險結構度量，不預測漲跌、不提供任何買賣建議。資產參數（波動率、最大回撤、相關係數）為學術文獻量級的長期估計值，非即時行情；場外基金按「類別級」口徑近似；相關係數矩陣為靜態基線，危機模組在其上做單向抬升，不具備預測相關性突變的能力；歷史回撤不代表未來。

## 特色

- **風險貢獻歸因**：每檔持倉「出資多少」vs「承擔多少風險」並排雙桿圖；負貢獻（對沖）明確標示「吸收波動」，不當成異常值。
- **有效押注數 ENB**：`ENB = min(N_eff, 1/(wᵀCw))`——把資金權重與相關性一起算進分散度量，同時抓「持倉高度相關」與「權重極度傾斜」兩種偽分散。
- **危機壓力測試**：相關係數只准升、不准降（`crisisRho` 鐵律），數學保證危機波動 ≥ 平常波動；輸出危機波動率與分散力衰退幅度。
- **結構健康評分**：六維度加權（集中度 18%／錯配 30%／分散度 15%／危機韌性 12%／重疊 10%／絕對風險 15%）；錯配維度只罰「因相關性多吃的風險」，經「加入防禦資產不得降分」性質測試把關（84 組對照＋2000 組隨機，0 次違例）。
- **代碼直輸**：場內 ETF 代碼、19 個場外基金聯接代碼、台股帶交易所後綴代碼、中文名稱模糊匹配，全部識別。
- **優化模擬**：只對「有實質錯配」的組合作調倉建議（錯配 × 組合波動 > 2 個百分點才提示），避免低波動組合被噪音誤導。
- **分享卡片**：一鍵生成 1080×1440 風險體檢卡長圖，存圖分享。
- **全本地計算**：零 npm 依賴、斷網可用，持倉資料不離開裝置；簡繁雙語在引擎層產出（`analyze(holdings, {lang:'tw'|'cn'})`），不是 UI 字串替換。

## 快速開始

三種跑法，按場景選。

### 方式一：微信小程式

用微信開發工具匯入 `miniprogram/` 目錄，AppID 選「遊客 AppID」即可預覽（基礎庫已鎖定 3.5.5，分享卡依賴 `canvas type="2d"`，需 2.9.0 以上）。

### 方式二：H5 網頁

```
瀏覽器直接打開 web/index.html          # 無需伺服器、無需構建
或雙擊 deliverables/持倉透鏡_H5演示_单文件.html   # 引擎已內聯，離線可用
線上演示：https://jerry19750106-code.github.io/holdingslens/
```

### 方式三：本地腳本（Node 20+）

```bash
node tests/engine.test.js    # 引擎不變量測試（126 項）
node verify-mp.js            # 小程式靜態自檢（17 項）
node verify-web.js           # H5 靜態自檢（15 項）
node build-web.js            # 重新打包 H5 bundle
node build-standalone.js     # 重新生成 H5 單檔案版
```

改 `tests/engine.test.js` 頂部的持倉即可批量分析自己的組合。

> **注意**：小程式無法引用專案根目錄之外的模組，因此引擎在 `miniprogram/shared/` 有一份副本，與 `shared/` 保持位元組級一致（md5 相同）。修改引擎後請同步副本，並重新打包 H5。

## Demo 案例（引擎實跑輸出，非編造）

輸入：A股成長 18 萬＋美股科技 15 萬＋黃金 6 萬＋中國債 4 萬（合計 43 萬）

| 資產 | 資金權重 | 風險貢獻 | 判讀 |
|---|---|---|---|
| A股成長 | 41.9% | **60.2%** | 超配 18.3 個百分點，風險高度集中 |
| 美股科技 | 34.9% | 37.4% | 略超配，與 A股成長高度聯動 |
| 黃金 | 14.0% | 2.5% | 優質分散，低風險高性價比 |
| 中國債 | 9.3% | **−0.2%** | 負貢獻＝對沖，吸收組合波動 |

- 組合波動率：正常 **17.2%** → 危機 **19.5%**（+13.4%）
- 分散力衰退：**41.5%**（危機中分散效果大幅縮水）
- 有效持倉數 nEff **3.1** ｜ 有效押注數 ENB **2.3**（名義 4 檔，考慮正相關後真正獨立的押注只有 2.3 筆）
- 結構健康評分：**62 / 100（基本穩健·有偏科）**
- 調倉模擬（唯一觸發實質性門檻的建議）：A股成長的 20% 轉到中國債 → 波動率 17.2% → 15.1%，最大單一風險佔比 60% → 52%

**對照組（同一引擎實跑）**：

| 組合 | 波動率 | nEff | ENB | 健康分 | 評估 | 押注提示 |
|---|---|---|---|---|---|---|
| **Demo**（成長18萬/美科15萬/金6萬/債4萬） | 17.2% | 3.1 | **2.3** | **62** | 基本穩健·有偏科 | 偽分散 |
| 保守型（債40/紅利25/金15/現金20） | 5.2% | 3.5 | 3.1 | **78** | 基本穩健·有偏科 | — |
| 均衡型（A股寬基25/美股25/中國債25/黃金15/港股10） | 9.7% | 4.5 | 3.1 | **77** | 基本穩健·有偏科 | 偏集中 |
| 股債平衡（A股寬基60/中國債40） | 12.0% | 1.9 | 1.9 | 56 | 結構偏脆弱 | — |
| 跨國雙股（A股成長50/美股科技50） | 21.8% | 2.0 | 1.4 | 58 | 結構偏脆弱 | 偽分散 |
| 全押中港 5 類等權 | 20.3% | 5.0 | **1.2** | 56 | 結構偏脆弱 | 偽分散 |
| 單押 A股（成長50/中小盤50） | 25.6% | 2.0 | 1.1 | 49 | 結構偏脆弱 | 偽分散 |
| 100% A股寬基 | 20.0% | 1.0 | 1.0 | 51 | 結構偏脆弱 | — |
| 99.9% 加密＋3 筆零頭 | 59.9% | 1.0 | 1.0 | 40 | 結構偏脆弱 | 偽分散 |

注意第三列與第四列：名義持倉 5 檔、nEff 5.0「看起來很分散」，ENB 只有 1.2——這正是偽分散的數學肖像；ENB 同時受權重影響，99.9% 單押加密加三筆零頭的組合，ENB 也只有 1.0。健康分方向經過性質測試把關：加入債券或現金等防禦資產只會加分、不會扣分。

## 決策記錄

本專案經過四輪外部評審（Claude ×2、Gemini ×2，含 Python 獨立交叉驗算）與一輪使用者親驗，以下是影響成品形態的最終決定——全部記錄在此，供評審與貢獻者檢視：

| # | 議題 | 最終決定 | 理由與證據 |
|---|---|---|---|
| 1 | ENB（有效押注數）公式 | 採用 `ENB = min(N_eff, 1/(wᵀCw))` | 舊版不考慮資金權重：99.9% 押加密＋三筆 0.03% 零頭，ENB 3.9「無風險集中」。新版同時計入資金權重與相關性，11 組情境經 Python 獨立驗算全部吻合；上限截 N_eff，防止對沖組合的 ENB 超過持倉筆數 |
| 2 | ENB 固定閤值 1.8 / 2.8 | **不採用**，保留依持倉數縮放的偽分散判定 | 固定閤值會把「債 70／現金 30」（ENB 1.61）誤報為偽分散，又會漏報「10 筆押 3 筆」 |
| 3 | 健康評分錯配基準 | 由「風險佔比 − 資金佔比」改為「風險佔比 − 獨立波動佔比」（wᵢσᵢ/Σwⱼσⱼ） | 使用者親驗硬傷：舊口徑「加債券反而扣分」——100% 成長 48 分，股債 50/50 只剩 32 分，126 組對照 117 組降分。新口徑只罰「因相關性多吃的風險」，修復後 84 組對照＋2000 組隨機 0 次違例 |
| 4 | 危機相關性 | `crisisRho` 遇現金維持原相關（return base） | 數學保證 σ_crisis ≥ σ_normal 是結構性成立，不是調參調出來的；實測全現金 0.5%→0.5%、債+現金 3.6%→3.6%，5000 組隨機把關 |
| 5 | 「Meucci 定義」「特徵值」表述 | 刪除 | ENB 公式已改版，避免引用陳舊定義誤導評審 |
| 6 | H5 發布 | GitHub Pages | 零伺服器成本，評審與使用者直接開連結即可體驗 |
| 7 | 小程式送審 | **不送審，只交原始碼** | 微信金融類目需相應資質；本作品以比賽／作品集演示定位，不做商業發布 |
| 8 | 新增 5 個場外基金代碼 | 不加 | 無對照組驗證，違反雙軌驗證紀律；寧缺勿濫 |
| 9 | 100% 現金組合評語 | 選做，未做 | 屬文案打磨，不影響數學正確性；優先把資源放在硬傷修復 |

## 開發紀律

- **雙軌驗證**：靜態（grep／AST／JSON 解析）＋行為（匯入真碼，不 mock 路徑）；每個修復先證明測試會失敗，再修改到通過。
- **每個數字同輪附證據**：金額與統計一律用程式核算，不心算、不轉述；測試結論以實跑輸出為準。
- **修改 bug 時先列出所有同類問題，再逐一處理**，不漏修。
- **綜合評分必須過性質測試**：案例全對不等於方向正確——「加入債券／現金等防禦資產，健康分不得下降」這類單調性把關，正是靠它抓到「加債券反而扣分」的硬傷。
